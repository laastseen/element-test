# Практикум «От Python к 1С:Элемент» с тестом

Встроены 10 заданных вопросов без отметок правильных ответов. Перед началом студент вводит ФИО и группу. Начало попытки, ответы и результат сохраняются в Supabase. Незавершённые попытки видны преподавателю. Существующие учебные шаги сохранены.

## Файлы

- index.html — практикум с разделом «Тестирование».
- admin.html — кабинет преподавателя.
- config.js — адрес Supabase и публичный ключ проекта.
- api.js, questions.js, quiz.js, admin.js — код сайта.
- supabase.sql — таблицы, права доступа и функции базы.

Публикуйте все HTML и JS файлы вместе в одной папке. SQL и эту инструкцию публиковать не требуется. Подходит для статического хостинга, в том числе GitHub Pages. Изменять сервер хостинга не нужно.

## Подключение Supabase

1. Создайте проект на https://supabase.com/dashboard или используйте отдельный учебный проект.
2. Откройте SQL Editor, вставьте весь supabase.sql и выполните. Скрипт не удаляет существующие результаты; использует собственные имена таблиц и функций.
3. В Connect / API Keys скопируйте Project URL и публичный Publishable key (либо legacy anon key).
4. В config.js заполните supabaseUrl и supabaseKey. В браузерный код нельзя вставлять Secret key или service_role.
5. В Authentication → Users → Add user создайте учётную запись преподавателя с email и паролем; подтвердите email через предусмотренный интерфейс (Auto Confirm User). Публичная форма регистрации на сайте отсутствует.
6. Назначьте этой записи право просмотра. Выполните в SQL Editor, заменив адрес на email созданного преподавателя:

```sql
insert into element_private.admins(user_id)
select id from auth.users
where lower(email) = lower('teacher@example.com')
on conflict do nothing;

select u.email
from element_private.admins a
join auth.users u on u.id = a.user_id;
```

Последний запрос должен вернуть email преподавателя. Если список пуст, проверьте адрес и наличие пользователя.
7. Опубликуйте HTML и JS файлы. Откройте admin.html или ссылку «Вход преподавателя» внизу практикума. Войдите email и паролем созданного пользователя.

Если закрытая схема element_private вручную была добавлена в настройки Exposed schemas, удалите её оттуда. Она не должна быть доступна через Data API. Для этого сайта достаточно стандартной открытой схемы public.

## Что видит студент

Форма ФИО и группы, десять вопросов по три варианта, количество заполненных ответов. Отправка разрешена после ответа на все вопросы. Результат показывается только после успешного сохранения в базе. Если связь пропала, ответы остаются на странице и отправку можно повторить. Повторная отправка завершённой попытки возвращает уже сохранённый результат, не изменяя его. Не обновляйте и не закрывайте страницу во время теста: восстановление незавершённой работы после перезагрузки не предусмотрено.

По 1 баллу за правильный ответ: 9–10 — «5», 7–8 — «4», 5–6 — «3», 0–4 — «2». Эту шкалу можно изменить в функции element_submit в SQL; тогда обновите описание шкалы в quiz.js.

## Что видит преподаватель

Все начатые и завершённые попытки, ФИО, группу, время, длительность, баллы и оценку. Есть поиск по ФИО, фильтры по группе и статусу, подробные ответы, постраничный вывод и CSV для Excel. Время отображается в часовом поясе браузера преподавателя. CSV содержит текущую отфильтрованную выборку, включая все её страницы.

ФИО и группа сообщаются самим студентом, без проверки личности. Не используйте это как систему подтверждения личности на экзамене. Повторное прохождение разрешено; каждая новая попытка появляется отдельно. При закрытии страницы попытка остаётся в статусе «Начата»; это не означает, что студент сейчас онлайн.

## Как устроен доступ

Браузер не отправляет балл или оценку: база вычисляет их по закрытому ключу. Анонимным посетителям запрещены чтение таблицы и прямое изменение результатов. У студента есть только функции создания попытки и однократной отправки по случайному токену. Токены и ключ ответов хранятся в закрытой схеме. Для преподавателя используются Supabase Auth и отдельная таблица назначений прав; сам по себе вход обычного пользователя прав не даёт. Пароль преподавателя и ключ ответов не записаны в JS файлах сайта. Сессия админки хранится в памяти вкладки, после обновления страницы нужно войти снова.

Публичное создание попыток открыто всем посетителям сайта. Лимита на количество попыток и защиты от автоматического заполнения в этой версии нет.

## Проверка после подключения

1. Пройдите тест от имени тестового студента. Все верные ответы должны дать 10/10 и оценку 5.
2. Проверьте попытку с неверными ответами и соответствующую оценку.
3. Откройте админку, проверьте группу, время, ответы и выгрузку CSV.
4. Откройте сайт в приватном окне без входа. Получить общий список попыток должно быть невозможно.
5. Убедитесь, что учётная запись, не добавленная в element_private.admins, не может открыть результаты.
6. Проверьте отправку при временном отключении интернета: после восстановления связи повторная отправка должна сохранить один итог.

При подготовке проверены в браузере: переход к тесту, ошибка при отсутствии конфигурации, 10 вопросов, повторная отправка после сетевого сбоя, показ результата, вход преподавателя, подробные ответы, экранирование введённого HTML и выход. API базы в этих проверках подменялся тестовыми ответами. SQL и работа с настоящим Supabase не проверены: аккаунт Supabase пока не подключён, адрес и ключ проекта не предоставлены.
